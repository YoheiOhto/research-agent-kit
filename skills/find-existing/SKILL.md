# 実装前に既存のものを探す

既存コードの発見は実装・共通化・実験の許可ではありません。研究実装は受入先の計画・Issue・対象版への明示承認を満たした範囲で行います。このスキル自体はファイルを変更しません。

## 一度の限定した探索

依頼、近くのプロジェクト指示、既存の入口を読み、探す機能と候補範囲を決めます。存在する場所だけを対象にし、ルート全体・全履歴・データ・出力を無制限に走査しません。結果は必要なパス・行・件数に絞ります。

1. 共通ライブラリとその目次を確認します。データ読込み、分割、指標、モデルなど、定義がずれると結果が変わる処理を優先します。`lib/`という名前は必須ではありません。
2. 既存の重複候補・未対応事項があれば確認します。既に統合待ちの処理を新しく書きません。
3. 類似実験とExampleを探します。関数名だけでなく、入力列、指標、アルゴリズムなど機能固有の語で検索します。入力・出力、引数、依存、検証状態、元のrevisionを読み、今回の条件に合うか確認します。
4. 許可されたローカルの差分や作業一覧で並行変更を確認します。同じ仕事が進行中なら競合箇所を報告し、重複実装へ進みません。remoteへのアクセスや他人の変更は行いません。

## 判定と返答

| 判定 | 提案 |
|---|---|
| 既存あり | 呼出し先と、今回の入力・条件に適合する根拠を示す |
| 類似あり | 共通点・差分・拡張候補を示す。類似を未発見扱いにしない |
| 今回の範囲では未発見 | 調べた場所と限界を示す。不在を証明したとは言わない |

チャットで探索範囲、候補の`path:line`、再利用可否、未確認点、次の提案を返します。別の探索報告書は作りません。

設定だけが違うvariantは、既存runnerに明示した設定を渡せるか先に検討してください。実験一式のコピーを既定にせず、新規ファイルや共有ライブラリの変更が必要なら理由と影響範囲を示します。共通化、別実験の置換、Example登録、Git操作へは、それぞれ依頼された範囲でのみ進みます。過去の科学的条件や承認ファイルを新実験へ流用しません。
