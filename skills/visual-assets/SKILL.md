# 図・画像を選び、生成・編集する

利用者の依頼と受入先の規則に従い、必要なassetだけを作ります。このスキルには画像backend、モデル、認証、課金API、依存パッケージは含まれません。導入だけで生成・外部送信・実験の実行許可が得られるわけではありません。

## 最初に制作方法を選ぶ

| 必要なもの | 方法と境界 |
|---|---|
| 実験の数値を示す図 | 保存済みの検証された表と描画コードから作る。単位・分母・不確実性・欠損/失敗を保持し、表・コード・出典を残す。生成AIや手描きで点・曲線・数値を捏造しない |
| 仕組みや関係を伝える概念図 | 説明用と明示し、与えられた構造に沿ってSVG・図式・コード等を選ぶ。実測値や観察画像のように見せない。正確な文字・配置が必要なら編集可能な表現を優先する |
| 写真風画像・イラスト・素材 | 利用できる画像生成ツールで依頼された場面・用途を表現する。研究の実写・観測証拠と混同させない |
| 既存画像の変更 | 対象を実際に見てから、変更箇所と保持する内容を分け、対応する画像編集ツールを使う |

研究図の作成依頼は新分析・実データ処理・モデル実験の許可ではありません。必要な追加処理があれば、受入先の計画と承認に戻します。画像の依頼だけでHTMLページや別の報告書を追加しません。

## 実在するツールと依頼範囲を確認する

現在利用できるtoolと、その入力・編集・出力仕様を確認します。利用可能なnative画像ツールがあれば優先し、存在しない機能・特定モデル・無料枠・自動保存先を仮定しません。

目的、使う場面、被写体、構図、縦横比、文字、背景・透明度、必要枚数を依頼から整理します。明らかな条件を聞き直さず、結果を左右する不足だけを確認します。対応していない設定を有効にしたと報告しません。

別APIやサービスへの切替、認証追加、依存導入、batch化、枚数・費用の増加は、既存の許可と実際の制限を確認し、不足する範囲だけ相談します。認証情報を出力せず、ツールが使えなければ制約と必要な選択を伝えます。無断で別backendへ送信しません。

## 一般画像を生成する

依頼の重要な内容、構図、画風、背景、文字、保持すべき条件を生成指示にまとめてください。実験の結果や利用者が与えていない事実を追加せず、必要な枚数だけを作ります。seedやサイズなどの指定はツールが実際に対応するときだけ使います。

生成後は画像を開き、依頼との対応、被写体、文字、構図、欠け、背景を確認します。修正が必要なら問題を具体化し、同じ依頼の許可範囲で調整します。見ることができなければ未確認と伝え、完成確認をしたことにしません。

## 画像を編集する

対象画像を先に開いてください。参照画像が不足・読取り不能なら、推測で代用品を使わず必要な画像を求めます。残す被写体、形、配置、文字、色、寸法、透明度など、依頼に関係する保持条件を確認して編集指示に含めます。

元画像を保全し、編集版は区別できる名前・版で保存します。別の構図を勝手に描き直さず、依頼された変更を優先してください。透明背景を求められた場合は、背景が白く見えるだけでなくalphaや縁の状態を確認します。透過入力を編集する場合も、変更依頼がなければ透過を保持します。

出力を実見し、変更箇所と保持条件の両方を比較します。文字の誤り、対象の欠落、予期しない切取り、解像度・透明度の変化があれば報告し、未解決事項を残します。

## 保存と引渡し

完成画像は利用者が指定・合意した保存先とプロジェクトの既存規約に従って置いてください。ツール内の一時保存先や一時URLだけを成果の参照先にせず、利用者がアクセスできる完成版を渡します。保存・取得を確認できない場合は、その制約を明示します。

元画像の識別、生成・編集内容、保持条件、実際に分かるtool/model、出力先、確認状況を既存の成果記録にまとめます。不明なモデル・設定・権利情報を補わず、画像ごとの別台帳や不要な中間版を増やしません。科学図では元表・描画コード・来歴を保全し、生成画像の記録と混同しません。

引渡しでは完成版の場所、行った変更、実際に確認した点、残る制限を短く伝えます。実見、保存、透明度確認のどれが未実施かを区別し、toolの成功応答だけで全て完了したとは言いません。
